# 写日记的流程（给 AI agent 的说明）

本文是写给 AI 编程助手（Claude Code、Codex 等）的操作说明：用户说“写昨天的日记”或“分析我的一天”时，照这里做。仓库根目录的 `CLAUDE.md` / `AGENTS.md` 会指向本文。你可以按自己的习惯改。English version: [diary-workflow.en.md](diary-workflow.en.md).

## 一、准备素材

1. **转写**：执行 `npm run run`（缺省处理昨天），得到 `transcripts/<日期>/`。指定日期用 `npm run run -- 2026-01-01`。
2. **检查认人**：执行 `npm run voice -- clusters <日期>`，看各个说话人簇在哪些时段说话、被认成了谁。常见的错误：
   - 上班时段大量出现家人的标签，多半是把同事认成了家人。用 `npm run voice -- add-cluster <名字> <日期> <录音> <簇号>` 把这一簇登记成这位同事，跑 `npm run voice -- check`，再用 `npm run transcribe -- <日期> --relabel-only` 重新认人。
   - 用户在录音里说“把这段用于声纹”时，用 `npm run voice -- add <名字> <录音> <开始> <结束>` 按时间段登记。
   - `clusters`、`add-cluster` 和不带 `--whole` 的 `add` 都要用 GPU 方案的缓存。只用 CPU 方案时，挑一段这个人单独、清楚说话的时间，用 `add ... --whole` 整段登记（最长 120 秒）。
   - 用 `add` 按时间段登记前，先对照转写稿确认那一簇是谁：在一对一的对话里，说话最多的那一簇往往是用户自己。必要时加 `--cluster` 指定。
   - 只见过一两次的人（活动、路人）不要登记，免得污染声纹库。新登记的非家人，阈值从 0.6 起步，重算后检查有没有在不相干的时段冒出来。
3. **读完全部转写稿**。太长时可以分块读，跳过广播、视频外放这类无关内容。用户常在录音里直接对 agent 说话（提问题、提要求），这些都要照办。建议和用户约定一个开头词（例如“diary”），带这个开头的就是给 agent 的任务。
4. **其他素材（可选）**：当天在电脑上的工作（比如 Claude Code、Codex 的会话记录）。如果能接入微信、飞书等聊天记录，也能一起分析当天的工作和生活消息。读聊天记录前先确认合规，聊天里的密码、密钥不要抄进日记。

## 二、日记结构

写到 `diary/<日期>.md`：

- **按时间线记事**：上午、下午、晚上，写发生了什么、去了哪、说了什么。引用原话尽量准确，后面括号注明音频位置。
- **旁观者视角**（必写），分四块：
  - **做得好的**：具体指出做对了什么，以及为什么好。
  - **可以做得更好的**：直说，不客套，并给出更好的做法；涉及常识或事实错误的，要指出正确说法。
  - **你可能没注意到的机会**：赚钱和幸福两方面，例如闲置资源、能变现的能力或作品、家人之间的情感时机。
  - **接下来可以试试**：1–3 件马上能做的具体小事。
- **你在录音里问的问题**：逐条回答，可以联网查，附上出处。
- **待办**：从对话里摘出来的事项。
- **录音情况**：录音覆盖了哪些时段，音频时间和实际时间的偏差，说话人标注是否可靠。

问题和待办都要简短。

## 三、规矩

- **每条观察都要有依据**：引用原话和时间，不凭空推测。录音只录到一部分时要说明，观察不等于定论。
- **话是谁说的，以声纹标签为准，但标签可能出错**。拿不准的写“不确定”。批评用户之前，先核对那句话的标签，不要把别人的话算到用户头上。
- **先核对前提，再提批评**。家里的实际情况（谁接送孩子、谁哪天有空）、用户亲自试过的技术方案，都以 `memory/` 里记下的和用户的实测为准，不要拿常识或教科书上的说法去反驳。
- **建议必须做得到**：在用户家的实际条件下可行。家庭情况记在 `memory/` 里，用户纠正过的以纠正为准。
- **隐私**：录音、转写稿、日记只在本机（和你自己的 GPU 主机）上处理，不上传到其他网络服务，也不进 git（`.gitignore` 已经忽略了这些目录）。派子代理处理转写稿时，同样只在本机。

## 四、记忆

日记写多了，会积累很多关于用户的事实：家庭情况、常见的人、转写常听错的名字、用户的纠正。建议放在项目里的 `memory/` 目录，一条事实一个文件，再用 `memory/MEMORY.md` 做索引，并在 `CLAUDE.md` 里引用这个索引。`memory/` 已在 `.gitignore` 里，不会被提交。

每个记忆文件的格式：

```markdown
---
name: family-situation
description: 一句话概括，回忆时靠它判断相关性
metadata:
  type: user | feedback | project | reference
---

事实本身。feedback 和 project 类型后面再写 **Why:** 和 **How to apply:** 两行。
```

写之前先查有没有已经覆盖这件事的文件，有就更新；发现记错了就删掉。
